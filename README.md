# Hybrid Multi-Source Log Analysis & Reporting Engine

A Python research/portfolio project that creates synthetic Linux authentication and OpenStack-style log records, normalizes log messages into event templates, uses TF-IDF features with an Isolation Forest to score unusual records, and displays analysis and a downloadable incident report in Streamlit.

> **Important scope note:** The included benchmark records are synthetic examples generated by the scripts; they are not live enterprise logs. The current evaluation script derives labels from keywords and template frequency, so its results should be treated as a demonstration of the pipeline, not independent proof of production-grade detection accuracy. Do not claim a verified 100% real-world detection rate based on this synthetic setup.

## Pipeline overview

```text
Synthetic Linux/OpenStack logs
           |
           v
initialize.py
  Creates raw_logs/ and processed_logs/ and template-normalized CSVs
           |
           v
stage2_chaos_engine.py
  Adds sample incident strings, extracts TF-IDF features, fits Isolation Forest
           |
           v
processed_logs/ml_analyzed_logs.csv
           |
           +----> evaluate_metrics.py
           |       Writes processed_logs/evaluation_scores.csv
           |
           +----> stage3_report_dashboard.py
                   Streamlit dashboard and downloadable incident report
```

## Requirements

- Python 3.10 or newer recommended
- pip

## Quick start (Windows PowerShell)

1. Clone or download this repository, then open a terminal in the project directory.
2. Create and activate a virtual environment:

   ```powershell
   py -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

   On macOS/Linux, activate with `source .venv/bin/activate` instead.

3. Install dependencies:

   ```bash
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```

4. Generate the sample inputs and parsed templates:

   ```bash
   python initialize.py
   ```

5. Run the anomaly-analysis stage:

   ```bash
   python stage2_chaos_engine.py
   ```

6. Optional: calculate the demonstration evaluation metrics:

   ```bash
   python evaluate_metrics.py
   ```

7. Launch the dashboard:

   ```bash
   python -m streamlit run stage3_report_dashboard.py
   ```

Streamlit will print a local URL (usually `http://localhost:8501`) to open in your browser.

## Main files

| File | Purpose |
|---|---|
| `initialize.py` | Creates working directories, synthetic source logs, and parsed CSV files. |
| `stage2_chaos_engine.py` | Adds sample incident records, extracts TF-IDF features, fits Isolation Forest, and writes the analysis CSV. |
| `evaluate_metrics.py` | Calculates a demonstration classification report from the analysis CSV. |
| `stage3_report_dashboard.py` | Displays metrics, log records, and a downloadable report. |
| `requirements.txt` | Python package dependencies. |
| `experiments/` | Additional standalone/alternate prototypes supplied with the project; these are not required by the main workflow. |

## Generated files

The scripts create `raw_logs/`, `processed_logs/`, and `data/` locally. These are generated outputs and are excluded from version control by `.gitignore`. Run the steps above to recreate them.

## Limitations and safe use

- This is a learning/demo project, not a production Security Information and Event Management (SIEM) system.
- The scripts use generated examples and simple parsing assumptions. Validate on representative, appropriately sanitized datasets before drawing conclusions.
- An anomaly is not automatically a confirmed attack. Investigate alerts before taking action.
- Do not commit real authentication logs, credentials, API keys, `.env` files, or personal data.
